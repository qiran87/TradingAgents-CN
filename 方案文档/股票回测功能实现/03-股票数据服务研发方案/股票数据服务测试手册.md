# 股票数据服务测试手册

## 一、测试概述

### 1.1 测试目标

- 股票搜索接口
- 股票信息接口
- 历史行情数据接口
- 数据可用性检查接口

### 1.2 测试范围
- 后端API接口功能测试
- 数据完整性验证
- 错误处理测试

- 后端服务：FastAPI（运行在 http://localhost:8000）

## 二、测试方案

### 2.1 API接口测试

#### 测试1：股票搜索接口
**接口**: `GET /api/backtest/stock/search`

**测试用例**:
1. 按股票代码搜索：`keyword=000001`
2. 按股票名称搜索（英文）：`keyword=PINGAN`

**预期结果**:
- 返回 `success: true`
- 返回匹配的股票列表
- 包含股票代码、名称、市场等信息

#### 测试2：股票信息接口
**接口**: `GET /api/backtest/stock/info`

**测试用例**:
1. 查询有效股票：`stock_code=000001.SZ`
2. 查询无效股票：`stock_code=999999.SZ`

**预期结果**:
- 有效股票：返回完整股票信息和数据统计
- 无效股票：返回404错误

#### 测试3：历史行情数据接口
**接口**: `GET /api/backtest/stock/quotes`

**测试用例**:
1. 查询有数据的日期范围
2. 查询无数据的日期范围

**预期结果**:
- 有数据：返回行情数据列表
- 无数据：返回404错误提示

#### 测试4：数据可用性检查接口
**接口**: `GET /api/backtest/stock/quotes/check-availability`

**测试用例**:
1. 检查完整月份的数据可用性
2. 检查特定日期范围

**预期结果**:
- 返回数据覆盖率
- 返回缺失的交易日列表
- 返回是否可用的判断

### 2.2 数据完整性测试

#### 测试5：数据映射验证
验证从 `stock_basic_info` 到 `stock_info` 的数据映射正确性。

**验证点**:
- 股票代码格式转换正确（6位 → 000001.SZ）
- 市场信息映射正确
- 数据完整性统计准确

### 2.3 错误处理测试

#### 测试6：异常输入测试
1. 无效的股票代码格式
2. 无效的日期格式
3. 起始日期晚于结束日期

**预期结果**:
- 返回适当的错误信息
- 不导致服务崩溃

## 五、问题排查

### 5.1 常见问题

**问题1：服务无法启动**
- 检查：MongoDB 和 Redis 是否运行
- 检查：端口8000是否被占用
- 解决：`lsof -i :8000` 查看占用，`kill <PID>` 停止占用进程

**问题2：API返回404**
- 检查：路由是否正确注册（main.py中）
- 检查：API路径是否正确（/api/backtest/stock/*）
- 解决：重启服务加载新路由

**问题3：数据库查询无数据**
- 检查：stock_basic_info 集合是否有数据
- 检查：数据映射逻辑是否正确
- 解决：先同步基础数据，或使用已有数据的股票代码测试

### 5.2 调试建议

1. **查看服务日志**
   ```bash
   # 服务日志在 logs/ 目录下
   tail -f logs/webapi.log
   ```

2. **使用Swagger UI测试**
   - 访问 http://localhost:8000/docs
   - 找到 `backtest-stock-data` 分组
