# 回测历史记录管理服务测试执行手册

## 一、测试概述

本测试脚本用于验证回测历史记录管理服务的功能正确性，包括：
- 数据库索引初始化
- 历史记录的保存、查询、对比、删除功能
- API端点可用性
- 单元测试

## 二、前置条件

### 2.1 环境要求

- **Python**: 3.10+
- **MongoDB**: 运行中（默认端口27017）
- **依赖包**: pytest, pytest-asyncio, motor, pydantic

### 2.2 服务准备

**方式一：完整测试（需要后端服务）**
```bash
# 启动后端服务
./venv/bin/python3 -m app
```

**方式二：仅单元测试（不需要后端服务）**
- 只运行单元测试部分
- 直接执行测试脚本即可

## 三、测试脚本说明

### 3.1 脚本位置
```
tests/test_history_service.sh
```

### 3.2 脚本功能

1. **环境检查**
   - 检测Python环境（优先使用虚拟环境）
   - 验证MongoDB连接
   - 验证Redis连接（可选）

2. **数据库索引初始化**
   - 创建 `backtest_history` 集合索引
   - 包括唯一索引、复合索引、全文搜索索引

3. **单元测试**
   - 测试保存到历史记录
   - 测试获取历史记录列表
   - 测试带筛选条件的列表查询
   - 测试获取历史记录详情
   - 测试对比历史记录
   - 测试删除历史记录
   - 测试异常处理

4. **API端点测试**（需要后端服务）
   - 测试获取历史记录列表API
   - 测试保存到历史记录API
   - 测试对比功能API

5. **测试结果统计**
   - 显示通过/失败数量
   - 列出所有测试结果
   - 明确标识是否符合预期

## 四、执行测试

### 4.1 完整测试流程

```bash
# 1. 确保MongoDB运行
mongosh mongodb://localhost:27017

# 2. 启动后端服务（新终端窗口）
./venv/bin/python3 -m app

# 3. 执行测试脚本
./tests/test_history_service.sh
```

### 4.2 仅执行单元测试

```bash
# 直接执行测试脚本（后端服务未启动会跳过API测试）
./tests/test_history_service.sh
```

### 4.3 手动执行单元测试

```bash
# 使用pytest直接运行
./venv/bin/python3 -m pytest tests/test_history_service.py -v
```

### 4.4 初始化数据库索引

```bash
# 单独运行索引初始化
./venv/bin/python3 -m app.scripts.init_history_indexes
```

**✅ 测试通过**：
- 所有测试Case显示为 `PASS`

### 5.3 常见问题处理

**问题1：MongoDB连接失败**
```bash
# 检查MongoDB状态
brew services list | grep mongodb
# 或
systemctl status mongod

# 启动MongoDB
brew services start mongodb
# 或
systemctl start mongod
```

**问题2：pytest未安装**
```bash
# 安装pytest
pip install pytest pytest-asyncio
```

**问题3：索引冲突**
```bash
# 删除旧索引重新创建
mongosh mongodb://localhost:27017/tradingagents
db.backtest_history.dropIndexes()
exit

# 重新运行测试
./tests/test_history_service.sh
```

## 六、测试用例详情

### 6.1 数据库索引初始化测试

| 测试项 | 验证内容 | 预期结果 |
|--------|----------|----------|
| record_id_unique | 唯一索引创建成功 | 索引存在且为unique |
| user_id_created_at_idx | 复合索引创建成功 | 索引存在 |
| strategy_id_idx | 策略筛选索引 | 索引存在 |
| stock_code_idx | 股票筛选索引 | 索引存在 |
| text_search_idx | 全文搜索索引 | 索引存在 |

### 6.2 单元测试用例

| 用例ID | 测试名称 | 验证内容 | 预期结果 |
|--------|----------|----------|----------|
| UT-01 | test_save_to_history | 保存历史记录 | 返回record_id，数据库中存在 |
| UT-02 | test_save_to_history_not_found | 保存不存在的回测 | 抛出BacktestResultNotFoundError |
| UT-03 | test_get_history_list | 获取列表 | 返回records列表和总数 |
| UT-04 | test_get_history_list_with_filters | 带筛选条件查询 | 正确筛选出符合条件记录 |
| UT-05 | test_get_history_detail | 获取详情 | 返回完整历史和结果数据 |
| UT-06 | test_get_history_detail_not_found | 获取不存在详情 | 抛出HistoryRecordNotFoundError |
| UT-07 | test_compare_history | 对比记录 | 返回2-3条记录对比数据 |
| UT-08 | test_compare_history_too_many | 对比过多记录 | 抛出InvalidComparisonError |
| UT-09 | test_delete_history | 删除记录 | 记录从数据库删除 |
| UT-10 | test_delete_history_not_found | 删除不存在记录 | 抛出HistoryRecordNotFoundError |

### 6.3 API端点测试

| API端点 | 测试方法 | 预期结果 |
|---------|----------|----------|
| GET /api/backtest/history | 调用API | 返回success=true，包含records数组 |
| POST /api/backtest/{id}/save | 保存到历史 | 返回success=true，包含record_id |
| POST /api/backtest/history/compare | 对比历史 | 返回success=true，包含对比数据 |
| DELETE /api/backtest/history/{id} | 删除记录 | 返回success=true |

## 七、自动化测试集成

### 7.1 CI/CD集成

在CI/CD流程中添加测试步骤：

```yaml
# .github/workflows/test.yml
steps:
  - name: 启动MongoDB
    run: docker-compose up -d mongodb

  - name: 运行历史记录服务测试
    run: ./tests/test_history_service.sh
```

### 7.2 定时测试

使用cron定时执行测试：

```bash
# 每天凌晨2点执行测试
0 2 * * * cd /path/to/project && ./tests/test_history_service.sh >> logs/test_history.log 2>&1
```
