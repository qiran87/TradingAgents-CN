# 股票回测功能实现 - 项目总览（重新设计版）

## 📚 文档说明

本文档是**股票回测功能实现**的总体设计，采用**领域驱动设计（DDD）**方法，从**后端领域服务**和**前端页面模块**两个维度进行任务拆解，确保前后端协议完全对齐，子系统高度解耦。

**版本**: v2.0（重新设计）
**创建日期**: 2025-02-05
**需求文档**: `./需求文档/股票回测功能实现.md`

---

## 🎯 重新设计思路

### 设计原则

1. **后端按领域服务拆解**：以业务能力为单位，每个服务提供清晰的接口协议
2. **前端按页面模块拆解**：以用户界面为单位，明确调用哪些后端服务
3. **前后端协议对齐**：所有子任务文档的前后端API协议完全一致
4. **高内聚低耦合**：每个子任务独立开发、独立测试、独立部署

### 拆解方法

#### 第一步：后端领域服务拆解

**拆解维度**：以**业务能力/领域**为标准
- 每个服务负责一个明确的业务领域
- 服务之间通过API接口通信
- 对外提供RESTful API接口

#### 第二步：前端页面模块拆解

**拆解维度**：以**用户界面模块**为标准
- 每个页面负责一个明确的功能区域
- 明确调用哪些后端服务的API
- 通过组件组合实现复杂交互

#### 第三步：前后端配对

**配对原则**：
- 一个前端页面可能调用多个后端服务
- 一个后端服务可能被多个前端页面调用
- 每个子任务文档包含：该领域的前端+后端完整方案

## 📊 后端领域服务拆解

基于需求文档分析，识别出**8个后端领域服务**：

### 服务1：策略管理服务

**领域职责**：管理策略库、策略定义、策略分类

**核心能力**：
- 策略库管理（内置策略、自定义策略）
- 策略分类管理（趋势策略、震荡策略）
- 策略查询（列表、详情、搜索、过滤）
- 策略参数管理（参数定义、参数校验）
- 使用统计

**对外API接口**：
```
GET    /api/strategies                      # 获取策略列表
GET    /api/strategies/{strategy_id}       # 获取策略详情
GET    /api/strategies/categories           # 获取策略分类
POST   /api/strategies/{strategy_id}/validate-params  # 校验策略参数
```

**对应文档**：`01-策略管理服务研发方案.md`

---

### 服务2：交易日历服务

**领域职责**：交易日历管理、交易日查询

**核心能力**：
- 交易日历数据管理
- 交易日列表查询
- 交易日判断
- 节假日判断
- 前后交易日查询

**对外API接口**：
```
GET    /api/trading-days                    # 获取交易日列表
GET    /api/trading-days/info               # 获取交易日统计信息
GET    /api/trading-days/{date}             # 判断是否为交易日
GET    /api/trading-days/{date}/previous    # 获取前一个交易日
GET    /api/trading-days/{date}/next        # 获取后一个交易日
```

**对应文档**：`02-交易日历服务研发方案.md`

---

### 服务3：股票数据服务

**领域职责**：股票数据查询、数据可用性校验

**核心能力**：
- 股票基础信息查询
- 历史行情数据查询（日级别）
- 数据可用性校验
- 数据完整性检查

**对外API接口**：
```
GET    /api/stock/info                      # 获取股票信息
GET    /api/stock/quotes                    # 获取股票行情
GET    /api/stock/quotes/check-availability # 检查数据可用性
```

**对应文档**：`03-股票数据服务研发方案.md`

---

### 服务4：回测执行引擎服务

**领域职责**：回测任务管理、交易模拟、资金持仓管理

**核心能力**：
- 回测任务创建和初始化
- 交易模拟执行
- 资金持仓管理
- T+1交易规则实现
- 100股倍数规则约束
- 任务状态管理

**对外API接口**：
```
POST   /api/backtest/start                  # 启动回测任务
POST   /api/backtest/{backtest_id}/interrupt  # 中断回测
POST   /api/backtest/{backtest_id}/continue    # 继续回测
GET    /api/backtest/{backtest_id}/status       # 查询回测状态
DELETE /api/backtest/{backtest_id}             # 放弃回测
```

**对应文档**：`04-回测执行引擎服务研发方案.md`

**领域职责**：回测进度跟踪、实时信息推送

**核心能力**：

## 🚀 开发策略

### 开发顺序（按依赖关系）

**第1阶段：基础服务（Week 1-2）**
- 服务1：策略管理服务
- 服务2：交易日历服务
- 服务3：股票数据服务

**第2阶段：核心引擎（Week 3-4）**
- 服务4：回测执行引擎服务

**第3阶段：支撑服务（Week 5-6）**
- 服务5：进度管理服务
- 服务6：结果计算服务

**第4阶段：扩展功能（Week 7）**
- 服务7：历史记录管理服务
- 服务8：导出服务

### 并行开发策略

**前端与后端并行开发**：
- 后端优先开发API接口和数据模型
- 前端使用Mock数据并行开发UI组件
- 后端API完成后，前端替换为真实API调用

**服务间并行开发**：
- 基础服务层（1-3）可并行开发
- 支撑服务层（5-8）在核心服务（4）完成后并行开发
