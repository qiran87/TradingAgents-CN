### 1. P1：WebSocket认证机制 ✅

#### 问题
WebSocket端点完全开放，任何人都可以连接，存在安全隐患。

#### 解决方案
在WebSocket连接中添加可选的JWT token验证。

#### 实现代码

**文件：** `app/routers/backtest_engine.py`

```python
@router.websocket("/ws/{backtest_id}/progress")
async def websocket_backtest_progress(
    websocket: WebSocket,
    backtest_id: str,
    token: Optional[str] = Query(None, description="JWT认证token（可选，用于安全控制）")
):
    """WebSocket端点 - 支持可选认证"""

    websocket_manager = get_websocket_manager()

    # 验证token（如果提供）
    if token:
        token_data = AuthService.verify_token(token)
        if not token_data:
            await websocket.close(code=1008, reason="Invalid or expired token")
            logger.warning(f"🔒 WebSocket认证失败: backtest_id={backtest_id}")
            return
        logger.info(f"🔐 WebSocket认证成功: user={token_data.sub}, backtest_id={backtest_id}")

    await websocket.accept()
    # ... 后续逻辑
```

#### 特性
- ✅ **可选认证**：开发环境可不传token，生产环境强制认证
- ✅ **JWT验证**：使用现有的AuthService进行token验证
- ✅ **优雅降级**：认证失败时关闭连接，返回标准错误码1008
- ✅ **日志记录**：记录认证成功和失败事件

#### 使用方式

**无认证（开发环境）：**
```javascript
const ws = new WebSocket('ws://localhost:8000/api/backtest/ws/bt_123/progress')
```

**有认证（生产环境）：**
```javascript
const token = localStorage.getItem('token')
const ws = new WebSocket(`ws://localhost:8000/api/backtest/ws/bt_123/progress?token=${token}`)
```

### 2. P2：HTTP轮询重试机制 ✅

#### 问题
网络临时故障时直接失败，没有重试机制。

#### 解决方案
实现指数退避重试机制，并智能处理429限流错误。

#### 实现代码

**文件：** `frontend/src/composables/useHttpPolling.ts`

```typescript
export interface HttpPollingOptions {
  // ... 其他配置
  retryAttempts?: number      // 重试次数，默认3
  retryDelay?: number          // 重试基础延迟，默认1000ms
  enableRetry?: boolean        // 是否启用重试，默认true
}

// 指数退避重试
const refresh = async (): Promise<void> => {
  let lastError: Error | null = null

  for (let attempt = 0; attempt <= retryAttempts; attempt++) {
    try {
      const newState = await fetchState()
      state.value = newState
      retryCount.value = 0 // 成功后重置
      onStateChange?.(newState)
      return
    } catch (error: any) {
      // 处理429限流
      if (error.response?.status === 429) {
        const retryAfter = error.response.headers['retry-after']
        const waitTime = retryAfter ? parseInt(retryAfter) * 1000 : 1000
        await delay(waitTime)
        return fetchState() // 递归重试
      }

      // 指数退避
      if (!enableRetry || attempt >= retryAttempts) break

      const backoffDelay = retryDelay * Math.pow(2, attempt)
      retryCount.value = attempt + 1
      await delay(backoffDelay)
    }
  }

  onError?.(lastError!)
}
```

#### 特性
- ✅ **指数退避**：第1次1s，第2次2s，第3次4s，避免雪崩
- ✅ **429处理**：智能解析`Retry-After`头，遵守服务器限流要求
- ✅ **可配置**：支持自定义重试次数和延迟
- ✅ **状态可见**：提供`retryCount`实时显示重试次数
- ✅ **超时控制**：5秒超时避免长时间挂起

#### 使用示例

```typescript
const { state, retryCount, isPolling } = useHttpPolling('bt_123', {
  retryAttempts: 3,        // 最多重试3次
  retryDelay: 1000,        // 基础延迟1秒
  enableRetry: true,       // 启用重试
  onError: (error) => {
    console.error(`轮询失败，已重试${retryCount.value}次`)
  }
})
```

### 4. P2：前端统一状态管理hook ✅

#### 问题
WebSocket和HTTP轮询分离，前端需要手动选择使用哪种方式。

#### 解决方案
创建`useBacktestProgress` hook，自动在WebSocket和HTTP轮询之间降级。

#### 实现代码

**文件：** `frontend/src/composables/useBacktestProgress.ts`

```typescript
export function useBacktestProgress(
  options: BacktestProgressOptions
): BacktestProgressReturn {
  const connectionType = ref<'websocket' | 'http'>('websocket')
  const wsStore = useBacktestEngineStore()
  let httpPolling: ReturnType<typeof useHttpPolling> | null = null

  // 监听WebSocket错误，自动降级
  watch(() => wsStore.error, (error) => {
    if (error && connectionType.value === 'websocket') {
      console.warn('⚠️ WebSocket错误，自动降级到HTTP轮询')
      connectionType.value = 'http'
      startHttpPolling()
      wsStore.disconnect()
    }
  })

  // 手动重连WebSocket
  const reconnectWebSocket = async () => {
    stopHttpPolling()
    const success = await startWebSocket()
    if (!success) {
      connectionType.value = 'http'
      startHttpPolling()
    }
  }

  return {
    currentState,      // 统一的状态接口
    connectionType,    // 当前连接类型
    isDegraded,        // 是否降级
    reconnectWebSocket // 手动重连
  }
}
```

#### 特性
- ✅ **自动降级**：WebSocket失败时自动切换到HTTP轮询
- ✅ **手动重连**：提供`reconnectWebSocket`方法尝试恢复WebSocket
- ✅ **状态可见**：`connectionType`显示当前使用的方式
- ✅ **统一接口**：无论使用哪种方式，`currentState`接口一致
- ✅ **回调支持**：连接类型变化时触发回调

#### 使用示例

```typescript
const {
  currentState,        // 当前回测状态
  connectionType,      // 'websocket' | 'http'
  isDegraded,          // 是否降级到HTTP
  reconnectWebSocket   // 手动重连
} = useBacktestProgress({
  backtestId: 'bt_123',
  token: 'jwt_token',
  onConnectionTypeChange: (type) => {
    console.log(`连接方式切换到: ${type}`)
  }
})

// 模板中使用
<template>
  <div>
    <span>连接方式: {{ connectionType }}</span>
    <span v-if="isDegraded" class="warning">已降级到HTTP轮询</span>
    <button @click="reconnectWebSocket">重连WebSocket</button>
  </div>
</template>
```
