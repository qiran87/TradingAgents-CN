## 测试概述

本测试手册用于验证"进度管理服务"的各项功能，包括：

- **WebSocket实时通信**：进度推送、持仓更新、交易信号
- **错误信息推送**：异常发生时的实时通知
- **HTTP轮询备用接口**：WebSocket不可用时的降级方案

## 测试验证点

### ✅ 必测项

| 序号 | 测试项 | 测试方法 | 验证标准 |
|-----|--------|---------|---------|
| 1 | 回测任务创建 | POST `/api/backtest/start` | 返回backtest_id，状态为created/running |
| 2 | WebSocket连接 | 连接`/ws/{backtest_id}/progress` | 收到connected消息 |
| 3 | 进度推送 | 观察WebSocket消息 | 每个交易日收到progress消息，percentage递增 |
| 4 | 持仓更新 | 观察WebSocket消息 | 收到position_update消息 |
| 5 | 交易信号 | 观察WebSocket消息 | 买入/卖出时收到trade_signal消息 |
| 6 | HTTP轮询接口 | GET `/{backtest_id}/current-state` | 返回当前状态信息 |
| 7 | 错误推送 | 触发异常（如无效股票代码） | 收到error消息 |

### 🔍 边界测试

| 测试场景 | 预期行为 |
|---------|---------|
| WebSocket断开后重连 | 自动重新连接 |
| 无效backtest_id | 返回404或WebSocket关闭(1008) |
| 回测完成后查询 | status为completed，execution_info包含最终结果 |
| 并发多个WebSocket连接 | 所有连接都收到相同的消息 |

### 📊 性能测试

| 指标 | 要求 |
|-----|------|
| WebSocket消息延迟 | < 100ms |
| HTTP轮询响应时间 | < 200ms |
| 并发连接数 | 支持10+个同时连接 |

## 故障排查

### 问题1：WebSocket连接失败

**症状：**
```
Error: connect ECONNREFUSED
```

**解决方案：**
1. 确认后端服务已启动：`curl http://localhost:8000/api/health`
2. 检查端口8000是否被占用：`lsof -i:8000`
3. 查看后端日志：`tail -f backend.log`

### 问题2：HTTP轮询返回404

**症状：**
```json
{"detail": "回测任务 bt_xxx 不存在"}
```

**解决方案：**
1. 确认backtest_id正确
2. 检查任务是否已被删除
3. 查看数据库中的任务记录

### 问题3：没有收到交易信号

**可能原因：**
1. 回测期间未触发买卖条件
2. 策略参数设置不当

**解决方案：**
1. 调整策略参数（如缩短日期范围）
2. 检查策略逻辑是否正确
3. 查看数据库中的交易记录：查询`backtest_trades`集合

### 问题4：前端无法连接WebSocket

**症状：**
浏览器控制台显示WebSocket连接错误

**解决方案：**
1. 确认后端CORS配置正确
2. 检查前端API_BASE配置
3. 使用浏览器开发工具Network标签查看WebSocket握手详情
